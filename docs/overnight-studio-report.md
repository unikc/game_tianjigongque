# 《天机宫阙》自主工作室夜间质量报告

## Executive summary

本轮以“先修可信度，再谈扩张”为原则，对当前 1–12 章版本进行了视觉、叙事、系统、移动端和技术审查。已修复结算存档恢复、损坏存档数值污染、移动端核心阅读尺寸、短屏行动布局、移动结算御印缺失、帝王关系选项不可达、关键道具离手后仍能使用、后续人物生死穿帮等高优先问题，并把失效的 SSR 检查纳入标准测试命令。

没有新增章节或系统。后半段“选项很多但状态回响不足”仍是商业质量的首要阻碍，不能用快速扩写掩盖。

## Before vs after

- 结算页退出后恢复会错误回到章节开头；现在 `evaluation`、第一章诏书及第 2–12 章结果检查点会恢复到正确结果界面。
- 320px 剧情正文约 14px、选项约 13px；现在为 17px / 15px，选项至少 52px 高，允许自然纵向滚动。
- 320px 寝宫五个行动被压成一排且说明只有约 8px；现在短屏改为两列，说明可换行、触控目标至少 56px。
- 移动端晋位御印被隐藏；现在保留 62px 御印并允许结果内容滚动。
- 第 2、3 章的帝信/帝宠专属选择按正常行动经济永远达不到；门槛已调整为前置章节可合法达到的 5 信任与 12 宠爱。
- 东珠或空印相关物件赠出/丢弃后，剧情仍允许拿它举证；现在物件不在珍藏时，对应选择不出现。
- PNG 母版随网站一起发布，生产目录约 28MB；母版已完整保留到 `art-masters/`，运行目录只保留 WebP，`public/` 约 2MB，重建后的 `dist/` 约 4.7MB。
- 标准 `npm test` 曾遗漏两项已失效的模板 SSR 测试；现在测试会先跑状态机，再构建并验证真正的产品 HTML。

## Playable content

- 姓名、三种家世、四种命宫。
- 第一章完整御前问答与位分评定。
- 第 2–4 章多场景分支：席位争夺、冷香疑案、雨夜空印。
- 第 5–12 章三幕式政治主线，直至十二种结局判定。
- 寝宫、人物、珍藏、行录四个长期页面。
- 修习、行动点、帝王宠爱/信任、三名核心人脉、晋位、珍藏赠予/丢弃、四个隐藏事件、存档续玩。

技术枚举仍能跑通：第一章 6,480 个组合、第二章 1,872 条终点、第三章 1,728 条终点、第四章 243 条终点，以及第 5–12 章各 27 条按钮路径。这里的“路径”表示不会断图，不代表每条都有足够独立的长期后果。

## Visual work

- 提升对话和选择的中文阅读尺寸、行距和触控高度。
- 320px 短屏寝宫行动区改成两列，去除极小字号与单行截断。
- 移动端结果/晋位重新显示御印，恢复章节高潮的仪式信息。
- 390×844 实测无横向溢出，核心第一场可完整容纳；320×568 通过容器内滚动承载长文本，不再缩字硬塞。

视觉总监复审认为人物页与章节封面是当前完成度最高的区域；寝宫、珍藏、身份选择和结算仍有成熟度差异。

## Art

本轮未生成新图，避免以风格不稳定的临时资产扩大不一致。现有 PNG 源文件未删除，统一移至 `art-masters/backgrounds`、`chapters`、`characters`、`items`、`protagonist`；线上只交付已确认被界面使用的 WebP。

现有角色、章节、场景和物件插图均保留。下一轮应优先补前四章独立封面、结算所得物件大图和角色裁切规范，而不是随机增加装饰。

## Narrative work

- 修复林栖梧可能已死亡却在第 7、8 章固定行动的穿帮：相关证词改由“旧案留下的证词”“掌握名册的证人”“旧案幸存者与宗卷”承接。
- 将固定“皇帝伤势反复/重病”改为能够容纳第七章多种结果的“猎场消息互相矛盾/久未亲自视朝”。
- “空印纸”改为“空印纹样”，使第四章不同处置仍能合理留下纹路拓记，同时避免宣称玩家必然持有原物。
- 关键物证现在与珍藏持有状态一致，赠出和丢弃具有真实后续代价。

叙事复审确认：第 1–4 章已形成“位置—名字—文书”的独特主题；第 5–12 章仍更像高质量剧情提纲，角色对白、信息分配和状态连续性不足。没有在一夜之间批量灌入文本。

## Gameplay work

- 恢复点修复，避免重复章节叠加属性、历史和奖励。
- 存档迁移新增家世/命宫白名单、属性 0–10 夹取、关系压力非负整数化；坏档会安全拒绝。
- 帝信与帝宠门槛调整到合法行动经济可达区间。
- 新增 `requiresRewardId` 条件，东珠验伪和空印反制必须真正持有物件。
- 测试增加损坏存档修复和所有结果检查点恢复验证。

尚未重做晋位判定：当前位分主要随章节自动提升，这仍削弱“靠策略成为皇后”的核心目标。

## Romance

本轮没有伪称“已完成恋爱线”。帝王宠爱/信任的两处剧情门槛已可实际触发，使数值首次更可靠地回流主线；但皇帝仍缺少完整、署名、具有政治分歧的双人戏。顾明华、裴照南、温疏雨的潜在线索已有主题，却没有正式的独立关系维度和阶段记忆。

## Audio

现有语义事件、总线、设置接口及 `data-audio-cue` 保留，所有音频缺失都会静默失败且不阻塞游戏。本轮未加入廉价循环古筝或来源不明的素材。当前没有真实消费者、静音设置或可听资产，因此游戏仍为静音；这是明确未完成项。

## Testing

- 专项审查：Imperial Art Director、Imperial Narrative Director、Systems/Strategy/Technical QA。
- 状态机：20 项 Vitest 全通过，包括 1–12 章分支枚举、12 个结局可达、旧存档迁移、损坏数据修复、成长/行动/隐藏事件、结果检查点恢复。
- SSR：生产构建后验证中文语言、产品标题、移动 viewport、首屏游戏内容、主 CTA、无旧模板骨架。
- 静态检查：Prettier、TypeScript、ESLint 全通过。
- 生产构建：vinext 五阶段构建成功，`/` 与 `/ids` 均生成。
- 实机视口：320×568 与 390×844。320 下正文 17px、选项 15px/52px、页面横向溢出 0；390 下横向溢出 0。
- 资源：`public/` 约 2.0MB，`dist/` 约 4.7MB，26MB PNG 母版仍可在 `art-masters/` 找回。

## Known issues

- 第 5–12 章的多数选择仍立即汇入同一场景，固定映射为谋略/人情/胆识；标签大量惰性，长期后果不够。
- 晋位主要按章节自动授予，宠爱、名望、盟友、失败和政治路线没有组成透明晋位条件。
- 皇帝、顾明华、裴照南、温疏雨尚未形成完整感情路线。
- 关系模型只正式追踪沈令仪、顾明华、高福安；后期重要 NPC 缺少可成长关系。
- 高福安死亡、裴照南失去资格、皇帝健康等状态仍未完全约束所有后续行动和 UI。
- 寝宫仍偏 dashboard，珍藏仍偏管理列表；首 30 秒身份选择仍像表单。
- 实际音频、静音/音量 UI、场景环境音尚未完成。
- 礼物选择弹层需要更完整的焦点捕获与 Escape 行为。
- `Game.tsx` 约两千行，控制器、页面与弹层耦合，回归风险较高。
- 当前是移动 Web/PWA 方向代码，不是可提交 App Store 的 Capacitor/Xcode 工程。

## Commercial-readiness assessment

- **Visual quality — 7/10。** 人物页、章节封面、对话场景已有鲜明宫廷身份；寝宫、珍藏、结算和初始选择仍不在同一成熟度。
- **Narrative — 6/10。** 前四章主题和政治谜案成立，后八章结构完整但呈现更像提纲，连续性仍有缺口。
- **Gameplay — 5/10。** 系统齐全且不易崩溃，但大量选择缺少延迟后果，晋位尚未成为真正策略目标。
- **Romance — 3/10。** 有数值、有角色化学反应的种子，没有完成任何可称为商业恋爱路线的弧线。
- **Audio — 1/10。** 有良好接口规范，无实际可听体验。
- **Polish — 6/10。** 核心移动阅读、触控、存档和资源包得到修复；焦点管理、动效因果和结果节奏仍需完善。
- **Technical quality — 7/10。** 全检查通过、分支枚举广、存档更安全、包体显著下降；单体组件过大且缺 UI 自动化。
- **Cohesion — 6/10。** 主题、色彩、文书语言和人物方向一致，但后段叙事深度、系统回响、音频与视觉成熟度不齐。

当前可作为有辨识度的本地 vertical slice 继续试玩，不建议以“12 章已经写完”为由进入 App Store 上架。商业绿灯需要先证明 2–3 个连续章节能稳定兑现延迟后果、晋位策略和一条真正的关系弧线。

## Top 5 next actions

1. 选第 7–9 章做一段商业质量样板：前置证据、人物生死、皇帝健康和关系必须改变后续场景，而非只改 outcome。
2. 重做晋位模型：公开 2–3 条竞争路径（帝心、名望/制度、人脉/政治），允许停滞、降级和恢复。
3. 完成一条皇帝政治感情线，并让顾明华、裴照南、温疏雨至少拥有可独立追踪的关系阶段。
4. 将 `Game.tsx` 拆为游戏控制器、剧情屏、寝宫、人物、珍藏、行录和弹层模块，并补关键 UI 自动化。
5. 在确认授权和声音方向后，实现 AudioEngine、持久化静音/音量和三枚高质量短 SFX；随后再评估环境音与音乐。
